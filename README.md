# Crime Hotspot Prediction & Visualization Dashboard

A micro project supporting the research paper *"An Intelligent Crime
Analysis and Hotspot Prediction System Using Ensemble Learning and
GIS-Based Visualization."*

Upload a crime dataset for any city/region, and the app will:
1. Label crime "hotspot" zones from spatial density
2. Train and compare **Decision Tree**, **Random Forest**, **XGBoost**, and an
   **Ensemble (soft-voting)** model on predicting hotspot occurrence
3. Show accuracy / precision / recall / F1 / ROC-AUC side by side
4. Visualize actual crime density and predicted hotspots on interactive maps
5. Export predictions and metrics as CSV for your paper's results section

## 1. Setup

```bash
pip install -r requirements.txt
```

(Python 3.10+ recommended.)

## 2. Run

```bash
streamlit run app.py
```

This opens the dashboard in your browser (usually `http://localhost:8501`).

No dataset yet? Check **"Use bundled sample dataset"** in the sidebar — a
synthetic 4,000-record dataset (`sample_crime_data.csv`, generated by
`generate_sample_data.py`) with three built-in hotspot clusters is included
so you can test the full pipeline immediately.

## 3. Bring your own dataset

Any CSV works as long as it has:

| Column        | Required? | Notes                                             |
|---------------|-----------|----------------------------------------------------|
| `latitude`    | Yes       | Decimal degrees                                    |
| `longitude`   | Yes       | Decimal degrees                                    |
| `crime_type`  | Optional  | Improves prediction signal                          |
| `date`        | Optional  | Used to extract month / day-of-week                |
| `hour`        | Optional  | 0–23, time of day the crime occurred                |
| `weapon`      | Optional  | Categorical                                          |
| `victim_age`  | Optional  | Numeric                                              |
| `status`      | Optional  | e.g. Open / Closed / Under Investigation             |

Good public sources: NCRB (India), data.gov.in, Chicago/LA/UK police open
data portals, Kaggle crime datasets.

If your columns are named differently, just rename them in the CSV (or in
pandas) to match the names above before uploading.

## 4. How "hotspot" is defined

The region is divided into a grid (cell size configurable in the sidebar,
default ~1.1 km). Each cell's crime count is computed, and cells at or
above the chosen percentile (default: top 25%) are labeled hotspots. Every
crime record inherits its cell's label.

**Important:** the grid coordinates themselves are deliberately *excluded*
from the model's input features. If they were included, a model could
trivially memorize "this exact location = hotspot" without learning
anything — a data leakage problem. Instead, the models predict hotspot
membership from the crime's *characteristics* (type, time of day, day of
week, month, weapon, victim age, case status). This is what makes the
comparison meaningful: it tests whether crime patterns, not just raw
location, carry predictive signal — directly supporting the research
paper's premise.

## 6. Extending for the full research paper

This micro project intentionally stays lightweight (single Streamlit app,
no auth, no database) so it's fast to iterate on for methodology
validation. If you later want to scale it toward the full system described
in the original scope document (Spring Boot + React + role-based access +
report generation, etc.), the ML logic in `ml_pipeline.py` is fully
decoupled from the UI and can be dropped into a Flask/FastAPI backend and
called from a React frontend without changes.
